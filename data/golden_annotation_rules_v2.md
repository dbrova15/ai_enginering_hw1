# Правила розмітки Schema v2

rules_version: `schema-v2-mentions-v1`. Статус: затверджено автором разом із 10/10 еталонами 26.10.2026.

### Область згадки

Одиниця оцінювання — заголовок і основний текст/таблиці/код із TXT **після однакової явної підготовки**. Рубрики «Плати», «Категорії», автор, реклама й навігація не є доказом. Оригінальний TXT не редагується; модель більше не отримує відомий службовий header під виглядом змісту. Заголовок зберігається з TXT; manifest/golden metadata не додаються до user text.

### Єдина підготовка тексту Schema v2

Мінімальна pure helper у чинному document_runner, не окремий NLP-конвеєр. Правило `schema-v2-text-v1` документується й фіксується до probes/baseline:

1. Прочитати оригінальний UTF-8 TXT без запису назад; source_sha256 рахується з первинних байтів. Для сформованого рядка детерміновано уніфікувати CRLF/CR у LF, не виправляти орфографію, числа або технічні назви.
2. Зберегти перший непорожній заголовок. Після нього розпізнавати лише відомий початковий службовий блок експорту: три наступні непорожні рядки з точними початковими мітками `Автори:`, `Категорії:`, `Плати:` у цьому порядку, значення — на тих самих рядках; між ними допустимі порожні рядки. Саме такий header знайдено в наявних English TXT. Це закритий профіль, не пошук усіх входжень слів у статті.
3. Видалити тільки три службові рядки розпізнаного блоку; решту рядків, включно з порожніми, заголовком, абзацами, code fences і кодом, зберегти. Поза цим початковим блоком нічого за whitelist не вирізати. Фраза «Категорії: датчики та приводи» всередині пояснення, рядок у code block, цитата чи звичайне слово «автор» зберігаються.
4. Неповна/інша послідовність не видаляється широким regex. До freeze процедури переглянути всі 30 джерел і підтвердити, що службові підказки не залишилися; сумнівний фактичний header вирішується вузьким задокументованим уточненням профілю до запусків, а не довільним очищенням. Невідомі рекламні/навігаційні фрагменти не видаляються NLP-евристиками; правила промпту не вважають їх доказом.
5. Фактичний user article string — результат цієї функції, без доповнення category/topic/language/tags/title з manifest або expected із golden. Для одного document ID він побайтово однаковий у всіх восьми конфігураціях; UTF-8 SHA-256 записується як input_text_sha256, поруч source_sha256 і text_preparation_version (або hash процедури). System prompt hash зберігається окремо.

Idempotence й output bytes визначені тестами: повторна підготовка не змінює результат. Процедура застосовується тільки до v2; v1 input behavior збережений. Ручна розмітка v2 звіряється з тією самою змістовою областю, а докази можуть посилатися на початкові рядки TXT. Freeze/порівняння контролюють input hashes; якщо підготовка змінюється після генерацій, старі runs належать іншому input version і не видаються за той самий експеримент. Це відрізняється від виправлення golden labels, для якого достатньо офлайнового перерахунку.

Підтверджена пряма згадка в основному змісті враховується й для альтернативи, майбутнього застосування або заперечення («без Bluetooth» містить згадку Bluetooth). Це тег згадки, а не твердження про встановлений модуль. Інструкції всередині статті лишаються недовіреними даними. Випадковий substring у змінній не дорівнює технічному терміну.

### Платформи та інтерфейси

| Випадок | Робоче правило |
| --- | --- |
| Arduino Uno/Mega, Arduino як плата/програмована платформа, Arduino sketch | arduino |
| Тільки Arduino Cloud, Arduino IDE або Arduino як виробник | Не доводить апаратну/програмовану платформу arduino; без іншої згадки тег відсутній |
| Wemos D1 mini без ESP8266 | Не виводити esp8266 |
| ESP32-C3/STM32F103, явно названі в тексті | Відповідна явно названа родина esp32/stm32, без взаємного виведення ESP32/ESP8266 |
| Raspberry Pi Pico з повною назвою | raspberry_pi; Pico без визначення в статті недостатньо |
| Wi-Fi/WiFi/Wi‑Fi; I2C/I²C | wifi; i2c за задокументованими написаннями |
| SPI.h/SPI.begin, LiquidCrystal I2C у коді/назві бібліотеки | Пряма згадка SPI/I2C дозволяє тег; Wire.h сам не доводить i2c |
| Serial, TX/RX без UART | Не виводити uart |
| LoRaWAN без окремого LoRa | Не давати lora без окремої згадки LoRa |
| Не перелічені платформи/інтерфейси | Не додавати new enum і не обирати найближчу категорію |

Словник написань у правилах один для всіх моделей. Це правила ground truth і промпту; evaluator v2 порівнює вже канонічні enum і не виправляє LLM `Wi-Fi` на `wifi` після отримання.

### Булеві поля

| Поле | Позитивна згадка | Не достатньо саме по собі |
| --- | --- | --- |
| mentions_sensor | датчик/сенсор/sensor, прямо названий тип датчика/термопара | Сам код BMP280 без пояснення в тексті, змінна sensorPin, вимірювання без згадки датчика |
| mentions_display | дисплей/екран/LCD/OLED, явно названий символьний/матричний/семисегментний індикатор | Звичайний LED живлення без дисплея |
| mentions_battery | батарея/акумулятор/battery, LiPo/LiFePO4 у контексті батареї | Самі 5V, блок живлення або «автономність» |
| mentions_motor | мотор/двигун/motor, сервопривід/кроковий двигун, прямо описаний електродвигун насоса | Реле/клапан або помпа без явного опису мотора |

Межі sensor/display/motor — рішення до погодження: не виводити клас компонента з довідкових знань про bare model. У review документувати докази як true, так і false (false — перевірено всю релевантну область тексту).

### Мова й головна тематика

language — домінантна мова авторського пояснення; code/ідентифікатори/короткі цитати не визначають її. За змішаного рівнозначного тексту потрібне ручне рішення до freeze. Модель не бачить metadata.language; metadata лишається незалежним полем envelope. Розбіжність golden.language із manifest діагностується й вирішується до затвердження, без тихого редагування manifest.

primary_topic обирається за головною метою статті, а не кількістю згаданих брендів. Пріоритет має предметний результат: автоматизація пристрою → devices_automation; прошивка/програмування контролера → controllers_programming; рух/привід → robotics_actuators; датчики/вимірювання/обробка вимірів → sensors_measurements; дисплей → displays_indicators; обмін даними/мережа → communications_iot; заряд/резервне живлення → power_batteries; виготовлення механічної деталі → printing_mechanics. Якщо головні цілі конкурують, зафіксувати домінантну тезу з джерела і ручне правило, не використовувати довільний алфавітний tie-break.

Обов’язкові окремі рішення за оригіналами: HR-0244 (пристрій/вимірювання), HR-0385 (полив/IoT), HR-0212 (живлення/автоматизація), HR-0227 (обробка вимірів/програмування). До погодження тут немає остаточних міток; v1-мітки/manifest не конвертуються автоматично в новий golden. Ці ручні рішення потрібні для остаточного golden, але не блокують незалежний код, probe чи baseline за робочими інструкціями.


LoRaWAN без окремої згадки LoRa не дає тег lora. Це закрите правило робочого контракту.
